Owning the mobile app at a remote US startup

{{co_d}} builds enterprise software for inventory management, construction and fleet management, which are the same areas the rest of this site covers. I own the mobile app, built in .NET MAUI. I work fully remotely with {{overlap}} of overlap with the US team each day.

Why this page is short. I started here in May 2026. That isn't long enough to judge the architecture I've shipped, so a full case study would be overselling it. This page covers what I own. The Hilti case study is where my depth is, and it's the one I'd rather be judged on.

Scope

What I own

  • The mobile architecture: the storage and sync model, module boundaries, threading rules, and the API contract I agree with the backend team.
  • Delivery: builds, signing, distribution and release checks, so shipping is routine and doesn't depend on a late night.
  • The technical standard: what I expect in review, reference code, and architecture rules that stop a young codebase from setting in bad shapes.
Domain

Why this fits

Inventory, construction and fleet are the same kind of problem I've worked on since Gallo Gateway: people in the field, rugged or shared devices, bad connectivity, and data where mistakes cost money. The product is new to me. The ways it can fail are familiar.

It's also the first time I've owned the mobile app with no engineer above me, and that's how I want to keep working.

Stack

Still .NET MAUI

Xamarin.iOS at Gallo, Xamarin.Forms at SmartSite, .NET MAUI at Hilti, and .NET MAUI here. Six years on the same family of frameworks means I've taken real apps through two framework migrations, and I know where each one's abstractions break down. You don't learn that from using the current version for a few months.
